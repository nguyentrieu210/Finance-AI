## Limitations
This is an internal prototype, not a secure public API. Custom PostgreSQL scope GUCs assume trusted application code and are not protection against arbitrary SQL by a compromised runtime. Only org creation command checks membership; raw scoped transaction is internal infrastructure, not an authorization decision. Direct runtime inserts are trusted-code privileges. Concurrent role revocation/TOCTOU, OIDC/JWKS, session revoke, delegation/SoD and full ABAC need implementation. Audit append-only privileges are tested; per-tenant hash chain, read/export, external anchor and retention not implemented. Outbox persistence only, no dispatch/inbox/job lease/fencing. No complete organization settings/hierarchy lifecycle or membership management. No payment or document endpoints, real data, AI provider, deployment or merge.

## Identity increment (synthetic-only)
Migration 20261127000500 adds a dedicated NOLOGIN non-BYPASSRLS, read-only identity lookup role and scoped RLS policies on the existing identity, membership, tenant and company tables (13 implemented tables; 70 planned). Rust finance-identity verifies compact JWT signatures with RS256 only, a restricted at+jwt profile, fixed issuer/audience, required exp/iat/sub, optional nbf, bounded token/key size, and expiring trusted JWKS snapshots. RSA modulus is restricted to 2048–4096-bit keys with exponent 65537; duplicate kid, weak keys, unexpected headers, unsupported algorithms and malformed tokens fail closed. VerifierStore atomically swaps a validated newer snapshot with the same issuer/audience; rejects rollback and removed keys. It does not fetch keys from token-provided URLs. After cryptographic verification, the resolver uses a separate least-privilege DB login and transaction-local verified issuer/subject and selected company scope; only an existing active identity, tenant, company and current membership can resolve to Principal::User. Token roles do not grant membership. No auto-provisioning or writes. Identity lookup GUCs are trusted application context, not a defense against arbitrary SQL under a compromised lookup login.

VPS evidence: fmt/clippy/build and 19 ordinary Rust tests pass; 4/4 real isolated PostgreSQL integration suites pass. Identity tests verify signed synthetic JWTs with two distinct generated RSA keys, signature mutation, wrong issuer/audience, expiry/nbf/iat, unsupported typ/alg, untrusted headers, weak/duplicate keys, expired snapshots and atomic key rotation/rollback. Real nonprivileged PostgreSQL lookup verifies membership, cross-company/tenant denial, expired/unknown subject denial, pool scope reset, write denial and membership revocation for a subsequent authentication. SQLx five migration replay/checksum drift, Spec/HTTP/table registry/OpenAPI and diff checks pass.

Limits: this is not full RFC 9068 compliance or a live OIDC integration. Trusted JWKS snapshot transport, pinned HTTPS discovery and live refresh scheduling, IdP-specific access-token profile (including Keycloak), client/session claims, logout/refresh/revocation, auth middleware, request binding to immutable verified principal, and authorization recheck in mutation transaction remain open. ## Permission increment (synthetic-only)
Migration 20261127000600 adds a narrowly scoped NOLOGIN permission guard role and fixed-search-path function. It locks existing tenant, company, subject and membership rows using FOR SHARE and evaluates active grants after lock acquisition, within the same READ COMMITTED transaction. Runtime cannot assume guard role; scope policies and WITH CHECK(false) protect guard's row-lock privileges. Rust finance-permissions supplies conservative RBAC/ABAC and SoD policy decisions for trusted resource facts, defaults to deny, rejects workers and mismatched scope, requires owner/assigned reviewer and independent approver, and does not enable delegation, grant administration or unsupported actions. Organization creation and audit reads now use the locked current-grant check, including authorization before idempotent replay. No new tables or public endpoints. Domain facts for future business actions must be loaded and locked from real resource repositories, not accepted from clients; this prototype does not implement full AuthorizationPort adapter or connect actual JWT authentication to every command. Row locks serialize changes to existing grants/status, not every possible new grant insertion, worker assignment, time expiry during long transactions or production session revocation. The test verifies membership revoke, not all policy lifecycle changes.

Real isolated PostgreSQL integration 5/5 passed: existing atomic command, jobs, audit, identity, and permission concurrency. Both lock-first and revoke-first scenarios tested; revoke blocks until command lock transaction finishes, command waits on pending revoke then denies, previously successful idempotent replay denied after revoke, no denied unit/audit effect, mismatched context and SET ROLE guard denied. SQLx six migrations replay and checksum drift rejection, spec/HTTP/table registry/OpenAPI validators and diff checks passed. No real records, production, or merge.
